# HEXA FRONTIER — 신규 프로젝트 게임 기획서 v2.0

> 대상: Claude Code 신규 프로젝트. 기존 코드/옛 기획을 전제로 하지 않는다.
> 상태: **확정된 제품 방향**과 **검증 전 밸런스 가설**을 명시적으로 분리한다.
> 작성 기준: 2026-11-12까지의 기획 대화. 이 문서는 대화 전문이 아니라 개발 가능한 핵심 의사결정의 정리본이다.

## 0. Claude Code에게 먼저 전달할 지시

1. 완전히 새로운 프로젝트 디렉터리에서 시작한다. 기존 HEXA FRONTIER 코드, 에셋, 문서를 자동으로 가져오지 않는다.
2. 이 문서를 우선 읽고 **확정 / 가설 / 미결정**을 구분한다.
3. 첫 응답에서는 코드를 작성하지 않는다. 핵심 루프, MVP 범위, 데이터 구조, 기술 스택, 리스크, 결정 질문을 보고한다.
4. 사용자가 설계를 승인한 뒤에만 구현한다. 기존 프로젝트를 삭제하거나 변경하지 않는다.
5. 단순 전투력 비교로 승패를 결정하지 말고, 실제 자동 전투 시뮬레이션을 설계한다.

## 1. 게임 정체성 — 확정

- 제목: **HEXA FRONTIER**.
- 장르: 헥사(육각형) 타일 탐험 + 스피릿 수집/육성 + 자동 전투 + 점진적 성장 RPG.
- 육성 대상의 공식 명칭: **스피릿(Spirit)**. UI, 코드 명명에 `spirit` 사용. `monster`는 적대적 야생 적에만 사용 가능하며 플레이어 육성 대상을 뜻하지 않는다.
- 핵심 참고 방향: **'탑과 용병단'식 성장과 막힘-돌파 재미**. 프리코네는 조합 다양성을 이해하기 위한 참고 사례일 뿐 핵심 지향점이 아니다.
- 주인공이 직접 전투 조작하는 방식이 아니라, 수집·편성한 스피릿이 전투한다.
- 속성 및 조합은 의미가 있지만 특정 희귀 스피릿이 없으면 스토리를 절대 못 깨는 구조는 금지.
- 기존 가족 캐릭터(은유·은결)는 이 게임에 포함하지 않는다.

### 플레이어에게 제공할 핵심 약속

> 보스에게 막혀도 해결 방법이 있다. 직접 탐험하고 성장시켜 당장 다시 도전하거나, 짧은 훈련/채집을 시작해 1~2시간 후 돌아와 돌파하거나, 긴 파견/오프라인 성장을 통해 다음 날 재도전할 수 있다.

- 긴 시간 플레이한 유저가 가장 빠르게 성장한다.
- 짧게 여러 번 접속하는 유저가 그다음으로 성장한다.
- 하루 한 번만 접속하거나 오래 방치해도 의미 있게 성장한다.
- 플레이 스타일은 계정에서 고르는 직업/모드가 아니라, 플레이 행동에 따른 **분석용 유형**이다. 유저는 언제든 세 방식을 혼합한다.

## 2. 핵심 게임 루프 — 확정 방향

1. 헥사 맵을 탐험한다.
2. 적을 조우하고 편성한 스피릿으로 자동 전투한다.
3. 경험치, 골드, 성장 재료, 해금 자원을 얻는다.
4. 스피릿 레벨/승급/스킬을 강화하고 조합을 바꾼다.
5. 보스에 도전한다. 패배 시 이유와 다음 성장 수단을 보여준다.
6. 즉시 파밍, 1~2시간 단기 활동, 장기 파견, 휴식 중 하나 이상을 선택한다.
7. 다시 도전해 보스를 돌파하고 다음 헥사 지역을 개방한다.

**필수 UX:** 패배 화면에서 부족한 요소(예: 공격, 생존, 상성, 피로)를 가능한 범위에서 설명하고, '지금 파밍', '1시간 훈련', '2시간 채집', '휴식', '편성 변경'으로 이어지는 행동 경로를 제공한다. 모든 패배를 전투력 부족으로 단정하지 않는다.

## 3. 탐험 및 전투 — 확정 방향 / 세부 미결정

- 헥사 타일을 이동하며 탐험하고 적과 조우한다.
- 전투는 스피릿 자동 전투. 스피릿 간 역할(탱커/딜러/힐러/지원/방해), 속성, 대상 선택, 스킬 차이를 둔다.
- 특정 상성이 있으면 더 쉬워지되, 다른 조합도 충분한 성장과 전략으로 일반 스토리 보스를 공략할 수 있어야 한다.
- 보스는 일반/지역 최종/선택형 고난도로 구분할 수 있다. 일반 보스는 긴 정체를 만들지 않는다.
- **미결정:** 전투 참여 스피릿 수(초기 제안 3 vs 3), 헥사 이동 규칙, 속성 개수(초기 제안 5), 스킬 수(초기 제안 2+필살기), 행동 주기, 승패 공식, 보스 패턴, 맵 생성 방식.
- MVP에서는 전투 결과를 수치 하나로 비교하지 않고 HP·공격·방어·속도·스킬·타깃팅을 갖춘 결정론적 시뮬레이션으로 시작한다. 난수는 시드 고정 가능해야 한다.

## 4. 스피릿 획득 — 확정 B안

- **성장 중심 획득 속도:** 초반 5~6종을 비교적 빠르게 확보하고, 이후에는 새로운 스피릿을 천천히 얻는다.
- 초기 운영 목표 가설: 중반 이후 신규 스피릿 약 **3~5일에 1종**. 이는 검증 전 목표이지 강제 보장 주기가 아니다.
- 스토리 진행만으로 탱커, 딜러, 회복/지원 등 필수 역할을 확정 확보할 수 있어야 한다.
- 뽑기 운, 희귀 등급, 특정 속성 미보유만으로 메인 스토리가 영구 차단되면 안 된다.
- 중복 획득이 필수 성장 조건이 되지 않도록 스피릿 조각의 비뽑기 획득 경로를 마련한다.
- **미결정:** 소환 방식, 확률, 희귀도, 천장, 재화, 조각 획득량. 유료 BM은 별도 결정 전까지 구현하지 않는다.

## 5. 성장 시스템 — 확정 구조 / 수치 가설

- 개별 스피릿 성장: **레벨(경험치)**, **승급(성장석)**, **스킬 강화(스킬석)**. 장기 확장으로 **진화(조각)**.
- 공통 재화 초기안: 골드, 성장석, 스킬석, 스피릿 조각. 불필요한 재화 종류 증식 금지.
- 초기 레벨 상한 가설: Lv.30. 1~10 빠름, 11~20 보통, 21~30 느림.
- 스피릿을 키운 자산이 신규 스피릿 획득 때문에 무가치해지지 않게 한다.

### 5.1 육성 투자 보호: E+F 혼합형 — 확정

**E. 따라잡기 성장 가속**
- 신규/저레벨 스피릿은 계정 내 육성 최고 레벨의 일정 비율까지 추가 경험치를 받는다.
- 가설: 최고 Lv.30이면 Lv.24(80%)까지 전투/훈련 경험치 **3배**.
- 자신의 실제 레벨과 승급/스킬은 별개로 유지. 가속 구간을 벗어나면 정상 성장.

**F. 선배 스피릿의 성장 경험 전수**
- 일정 수준 이상 성장한 선배 스피릿이 후배의 **훈련 경험치 보너스**를 제공한다.
- 가설: 선배 조건 충족 시 훈련 경험치 +30%.
- 선배 스피릿을 훈련장에 묶거나 전투에서 제외하지 않는다. 조건을 충족하면 자동으로 적용되는 계정 보너스에 가깝다.
- 가속/전수 중복 적용 순서와 상한을 명시해야 한다. 예: 기본 훈련 XP × 따라잡기 배율 × (1 + 전수 보너스), 상한을 둬서 폭주 방지.
- 무한 레벨업/부계정 악용/재료 복사 방지를 테스트한다.

## 6. 컨디션 B안 — 확정 구조

- 평소 일반 전투 승리로는 컨디션이 감소하지 않는다. **전투 패배, 치명적 피해, 전투불능**에서 피로가 발생한다.
- 컨디션 0~100, 신규 스피릿 100 시작. 컨디션 0이어도 출전 가능.
- 컨디션 저하가 반복 플레이를 강제로 차단하면 안 된다.
- 부상은 컨디션과 별개의 일시적 상태이며, 초기에는 **경상 한 단계**만 고려한다.

### 6.1 초기 수치 가설

| 컨디션 | 상태 | 공격/방어 효율 |
|---|---|---|
| 80~100 | 최상 | 100% |
| 60~79 | 양호 | 97% |
| 40~59 | 피로 | 93% |
| 20~39 | 지침 | 87% |
| 0~19 | 탈진 | 80% |

| 이벤트 | 컨디션 변화 가설 |
|---|---:|
| 일반 전투 승리 | 0 |
| 일반 전투 패배 | -5 |
| 보스 전투 승리 | 0 |
| 보스 전투 패배 | -8 |
| 전투 중 HP 30% 이하 경험 | -3 |
| 전투불능 | 추가 -10 |

- 전투당 총 감소 상한 **-15** (가설). 경상 발생은 전투불능 시 일정 확률(미결정), 공격력 -5% 추가 페널티(가설).
- 페널티는 초기에는 공격/방어에만 적용하고 최대 HP는 건드리지 않는다.

## 7. 휴식/치료 — 확정 방향 / 수치 가설

- 게임 미접속 중에도 컨디션 자연 회복.
- 휴식소는 더 빠른 회복을 제공하며, 배치 중 전투는 불가하되 언제든 중단 가능.
- 경상은 치료소에서 자원 소모로 즉시 치료하거나 휴식으로 해제.
- 가설: 자연 회복 시간당 +5, 휴식소 시간당 +15, 휴식소 2시간에 경상 해제, 휴식 슬롯 3개.
- 회복 시각은 서버 기준/신뢰 가능한 시간 기준으로 계산하고, 중복 보상 수령과 시계 조작을 방지한다.

## 8. 훈련/파견/오프라인 성장 — 확정 방향

- **훈련장:** 스피릿 경험치 획득.
- **자원 탐사대:** 골드/성장석/스킬석 획득.
- **유적 조사대:** 장기 파견으로 조각/희귀 재료 획득(후순위).
- 단기 활동 **1시간 훈련, 2시간 채집**, 장기 활동 **4/8/12/24시간**을 제공하는 방향.
- 짧은 활동은 시간당 효율이 높고, 긴 활동은 재접속 부담이 낮다.
- 파견 보상은 확정 기본 보상 + 선택적 희귀 추가 보상. 완료 후 즉시 수령하지 않아도 소멸하지 않는다.
- 파견 중인 스피릿은 전투 불가, 중단 가능. 중단 보상은 경과 시간 비례를 기본 제안으로 검토.
- 파견 자체는 컨디션을 감소시키지 않는다. 초기안으로 파견 중 자연 회복은 중단하여 휴식과 역할을 분리한다.
- **기본 방치 보상 + 파견**을 권장 설계로 둔다. 단, 사용자가 명시적으로 최종 확정하지 않은 오프라인 보상 세부 규칙은 **미확정**이다.
- 방치 보상은 파견 미설정 시에도 최소한의 성장 재료를 주는 방향이며, 무한 누적은 피한다(보관 상한 미결정).

### 8.1 자원 채집 보상 가설

| 시간 | 총 재료 | 시간당 |
|---|---:|---:|
| 1시간 | 20 | 20 |
| 2시간 | 36 | 18 |
| 4시간 | 64 | 16 |
| 8시간 | 112 | 14 |
| 12시간 | 144 | 12 |

이 표는 **동일 시설의 단일 슬롯 기준 가설**. 보상 테이블과 일일 실행 횟수를 함께 시뮬레이션해 과도한 접속 강제를 막는다.

## 9. 플레이 스타일과 성장 효율 — 확정 목표

플레이 스타일은 선택 화면에서 고정하지 않는다. 시뮬레이션과 운영 지표에만 사용한다.

| 분석 유형 | 대표 패턴 | 성장 효율 지수 목표 |
|---|---|---:|
| 집중 플레이 | 하루 1회 약 60분 | **100** |
| 수시 접속 | 하루 3~5회, 회당 5~10분 | **75** |
| 장기 방치 | 하루 1회 약 5분 | **50** |

- 확정된 **순위**: 집중 > 수시 > 방치.
- **100:75:50은 가상 목표 비율**. 실제 수치와 자원 구성은 테스트 후 조정한다.
- 가상 보상 분해: 집중=직접 60+파견 25+기본 15, 수시=직접 15+파견 45+기본 15, 방치=직접 0+파견 35+기본 15.
- 이 숫자는 자원 종류가 다른 보상을 임의 환산한 **설명용 모델**이며 실제 경제 공식이 아니다. 실제 시뮬레이터에서는 경험치/골드/성장석/스킬석을 각각 추적하고 보스 돌파 시점도 비교해야 한다.
- 플레이 강제 제한용 행동력/입장권은 초기 설계에서 사용하지 않는다.
- 반복 전투의 보상 효율 하락은 가설: 1~30회 100%, 31회 이후 70%. 다만 집중형이 최고 성장이라는 목표와 충돌하는지 반드시 검증하고, 첫 클리어 보상은 감소시키지 않는다.
- 하루 여러 번 접속해야만 보상을 잃지 않도록 설계한다. 파견 완료 보상은 보존한다.

## 10. 보스 정체와 돌파 시간 — 확정 경험 목표

- **아깝게 패배한 보스:** 1~2시간 단기 훈련/채집/회복으로 재도전해 돌파할 가능성을 제공.
- **일반 보스:** 오래 막히지 않는 성장 확인 지점.
- **지역 최종 보스:** 플레이 스타일에 따라 1~5일의 성장 여지를 둘 수 있음.
- 단순히 '2시간 대기 후 무조건 승리'를 보장하지 않는다. 패배 원인, 재료 필요량, 상성, 편성에 따라 다르다.

### 초기 검증 목표 (가설)

| 유형 | 일반 보스 | 지역 최종 보스 |
|---|---|---|
| 집중 플레이 | 당일 | 1~2일 |
| 수시 접속 | 당일~1일 | 2~3일 |
| 장기 방치 | 1~2일 | 3~5일 |

- 전투력은 안내용 보조 지표. 실제 승패는 스킬, 배치, 속성, 회복, 컨디션에 좌우된다.
- 보스 HP를 얼마나 깎았는지, 패배 원인이 무엇인지, 성장 후 얼마나 개선됐는지를 가시화한다.

## 11. MVP (첫 번째 플레이 가능 버전)

### P0 — '막힘 → 성장 → 돌파'의 재미 검증

- 헥사 맵 1개, 이동 및 조우.
- 스피릿 3종(탱커/딜러/지원 또는 회복), 일반 적 2종, 보스 1종.
- 간단한 자동 전투, 전투 결과, 전투 로그/시드.
- 경험치/레벨/골드/성장석 및 강화.
- 보스 패배 후 현재 가능한 성장 수단 안내.
- 1시간 훈련, 2시간 채집, 자연 회복 및 간단 휴식.
- 저장/재접속/시간 경과 보상 계산.
- 실제 1~2시간 대기를 기다리지 않고 테스트할 수 있는 **개발자 시간 가속 기능**.

### P1 — 성장 경로 완성

- 스피릿 5~6종, 확정 지급/획득 루프.
- E+F 따라잡기/전수, 컨디션 B안과 경상, 휴식소.
- 4/8/12시간 파견, 기본 오프라인 보상(승인 시), 편성/상성.
- 세 플레이 유형 7일 시뮬레이션, 경제 밸런스 대시보드.

### P2 — 확장

- 다지역 헥사 맵, 지역 보스, 스피릿 추가, 유적 조사/조각/진화.
- UI/아트/사운드 정교화, 밸런스 운영 도구.
- 계정, 서버, 상용화 및 BM은 별도 기획 승인 후.

## 12. 데이터 구조 초안 (확정 아님)

```text
SpiritDefinition: id, name, element, role, baseStats, skillDefinitions, targetingRules
OwnedSpirit: instanceId, definitionId, level, xp, rank, skillLevels, condition, injuryState
PlayerProgress: unlockedHexes, region, bossClears, currencies, spiritRoster
Battle: team, enemies, seed, actionLog, result, damageSummary, failureReasons
ActivityDefinition: id, type, durationSec, rewardTable, requirements
ActivityRun: id, type, assignedSpiritIds, startedAt, completesAt, status, claimedAt
GrowthBonuses: catchUpThreshold, catchUpMultiplier, mentorBonus, stackingCap
```

- 저장 데이터는 버전 관리한다. 보상 지급은 멱등 처리한다.
- 완료 시각, 클레임 상태, 중단 보상을 분리해 중복 수령 방지.
- 전투 시뮬레이션은 UI와 분리된 순수 로직으로 구현한다.

## 13. 반드시 수행할 테스트

1. 같은 초기 계정/같은 진행도로 **7일 집중/수시/방치** 패턴을 시뮬레이션한다.
2. 경험치, 골드, 성장석, 스킬석, 신규 스피릿 수, 보스 돌파 시점을 별도 측정한다.
3. 성장 효율 지수 목표 100:75:50을 참고하되 실제 자원별 병목과 보스 진행도를 우선한다.
4. 보스 HP 10~20% 남기고 패배한 시나리오에서 1시간 훈련/2시간 채집 후 돌파 가능성이 개선되는지 검증한다.
5. 불리한 속성/핵심 스피릿 미보유 계정도 과도한 정체 없이 메인 스토리를 진행하는지 검증한다.
6. 컨디션 0, 경상, 연속 보스 패배 상황에서도 플레이가 강제 중단되지 않는지 검증한다.
7. 신규 Lv.1 스피릿의 E+F 성장 가속이 기존 스피릿 육성 가치를 훼손하지 않고 실전 투입 시간을 줄이는지 확인한다.
8. 파견 중단/완료/보상 수령/앱 재실행/기기 시간 변경에서 중복 보상이 발생하지 않는지 확인한다.
9. 1시간 파견 반복이 12시간 파견보다 유리하되, 과도한 알람/재접속 강제가 없는지 확인한다.

## 14. 미결정 사항 및 개발 착수 전 질문

- 타깃 플랫폼과 엔진/프레임워크, 온라인 서버 필요성.
- 헥사 맵의 이동 규칙, 랜덤 생성 여부, 스테이지 구성.
- 전투 인원/속성/스킬/행동 순서/AI 규칙.
- 스피릿 획득 방식(확정 지급 외 뽑기/탐험/조각 비율), 희귀도.
- 오프라인 기본 보상의 최종 채택 및 누적 상한.
- 경험치 곡선, 스피릿별 레벨 격차, 스킬 강화 비용.
- 파견 슬롯/배치 제한, 중단 보상, 회복과 파견 동시 진행 여부.
- UI 아트 스타일 및 상용 BM.

## 15. 개발 원칙

- 기능을 많이 만드는 것보다 **막혔다가 돌파하는 재미**를 먼저 검증한다.
- 수치는 설정 파일/데이터 테이블로 분리해 코드 수정 없이 조정 가능하게 한다.
- 기획의 '확정 방향'을 지키되, 수치 가설은 시뮬레이션으로 조정한다.
- 기존 프로젝트는 건드리지 않는다. 이 문서만으로 새 프로젝트를 설계한다.
- Claude Code는 첫 단계에서 구현보다 **설계 검토 및 질문**을 우선한다.
